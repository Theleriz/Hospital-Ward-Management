`db/setup.sql` и синтетического `04_seed.sql`. Скрипт запущен с
`MEDBASE_DB_CONTAINER` этого источника. Восстановление шло в новый кластер,

## Остаточные замечания для Nurali

1. **Имя контейнера фиксировано.** `check-backup.sh:26–35,147` удаляет
   контейнер `medbase-backup-check`, что создаёт конфликт двух запусков на
   одном Docker-хосте. Использовать уникальное имя или ID конкретного
   контейнера, созданного текущим запуском. Перед своим прогоном я проверил,
   что этого имени нет в списке контейнеров.
2. **Права проверены через локальный сокет.** `check-backup.sh:45–48`
   запускает `psql` под `medbase_api` без указания хоста. Это доказывает
   права SQL-роли. Для проверки сетевой аутентификации добавить вход по TCP
   и убедиться, что пароль из рабочего окружения применён там, где нужен.
   Расширить проверки на `medbase_board`, `medbase_doctor`, `RetiredBadge` и
   новый журнал назначений, поскольку текущие сценарии проверяют исходные роли.
3. **Режим `umask` действует на новые файлы.** `backup-db.sh:13–28` принимает
   существующий каталог и пишет по имени с точностью до секунды. Для общего
   хоста создавать файл с уникальным именем внутри приватного каталога и
   проверять права каталога, который передан извне.
4. **Восстановление удаляет указанную базу перед импортом.**
   `restore-db.sh:40–49` использует имя цели из аргумента или конфигурации.
   Для длительного хранения и рабочих данных лучше проверять дамп во временной
   базе до переключения и обрабатывать имена базы и владельца как SQL-идентификаторы.

Исходные замечания к №20 закрыты для проверенного учебного прогона.
Остаточные замечания относятся к параллельным запускам и рабочему развёртыванию.

# PR #20 — Architecture & Security review

Reviewer: Kazbekio. Head: `11353f103ebc1532f469e1e4b1ac92d3130b44ae`.
Recommended event: REQUEST_CHANGES. Prepared 18 November 2026.

1. **Проверка восстановления фактически не выполняет SQL.** В
   `scripts/check-backup.sh` heredoc передаётся в `docker exec` без `-i`.
   stdin контейнера закрыт: psql не получает блок DO, скрипт печатает успех.
   Воспроизведено на одноразовом PostgreSQL 17: `SELECT 1/0` без `-i` даёт
   exit 0, с `-i` и ON_ERROR_STOP — exit 3. Добавить `-i` и отрицательный
   контроль: заведомо неверная схема должна приводить к провалу проверки.
2. **Дамп содержит данные пациентов и bcrypt-хэши.** Перед созданием файла
   установить `umask 077`, права нового каталога закрыть от других пользователей.
   `.gitignore` не защищает файл на диске; типичный umask 022 оставляет чтение другим.
3. **Права должны восстанавливаться вместе с данными.** Проверить medbase_api,
   SET LOCAL ROLE и отказ PublicStaff читать Patient. pg_dump не создаёт
   кластерные роли на новом сервере: предусловие восстановления нужно явно
   описать или обеспечить отдельным шагом. Проверка в том же кластере этот
   случай не доказывает.

Рабочая база команды не использовалась. После исправления нужны повторная

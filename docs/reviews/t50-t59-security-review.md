## Условия рабочего развёртывания

- **Доступ к входу без PIN.** В штатном режиме отсутствующий PIN даёт
  `422`. Для `MEDBASE_DEMO_BADGE_LOGIN=true` предусмотрена отдельная функция
  `fn_LoginStaffByBadge`. Выключенный флаг закрывает HTTP-ветку, а в схеме
  `EXECUTE` этой функции остаётся у `medbase_api`. Для Rishat и Nurali:
  вынести разрешение и установку функции в демонстрационный профиль и добавить
  SQL-проверку её недоступности в рабочем профиле.
  [Маршрут входа](../../backend/app/routers/auth.py) · [GRANT](../../db/07_badges.sql)
- **Токен коридорного экрана.** В текущем UI токен читается из URL и идёт
  в `X-Board-Screen`. `Referrer-Policy: no-referrer` сокращает утечку через
  переходы, но URL может сохраниться в истории и журнале первого запроса.
  Отзыв выполняется удалением токена из списка и перечитыванием конфигурации
  backend. Для Rishat: при подключении реального табло ограничить сети и обновить
  способ выдачи токена. [Клиент](../../frontend/src/board/api.ts) · [допуск](../../backend/app/routers/board.py)
- **Граница TLS.** Дополнительный HTTPS-вход сам по себе не включает
  `MEDBASE_SESSION_HTTPS_ONLY`. В локальном Chromium по HTTPS при конфигурации
  из Compose прошёл вход, полученная `medbase_session` была без `Secure`.
  Для Rishat: в рабочем профиле явно передать настройку backend, закрыть HTTP-вход
  и прямой доступ к портам backend и БД. [Конфигурация](../../backend/app/config.py) · [middleware](../../backend/app/main.py)

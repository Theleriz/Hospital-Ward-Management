# T-48 — блокировка PIN, сохраняющаяся после рестарта

Автор: Shynbulat Kazbek (Kazbekio), Architecture & Security, 18 ноября 2026.
SQL-часть подготовлена для ревью Nurali (Data & Database).

## Что изменилось

Раньше ошибки входа хранились в словарях Python. Теперь `fn_LoginStaff`
блокирует запись бейджа в PostgreSQL и в одной транзакции проверяет PIN,
считает ошибки и сохраняет пятиминутную блокировку. Часы backend не участвуют.
В таблице нет PIN и хэшей. Backend фиксирует транзакцию до ответа 401/429.
Старую функцию проверки PIN он напрямую вызвать не может.

Контракт: ошибки 1–5 → 401; во время блокировки → 429 и Retry-After, даже с
верным PIN. Срок не продлевается заблокированными обращениями. После его
истечения вход снова разрешён. Успех сбрасывает ошибки. Неверный формат → 422,
недоступная БД → 503 без выдачи сессии. Другие бейджи не блокируются.

## Демонстрация в VS Code

Из корня этой ветки выполнить:

```bash
bash scripts/check-login-lockout.sh
```

Скрипт поднимает отдельную БД и настоящий backend, отправляет пять неверных
PIN, получает 429, перезапускает backend и снова получает 429. Другой бейдж
получает четыре ошибки до рестарта и пятую после него — он тоже блокируется.
Выполняется второй рестарт и проверяется сохранение обеих блокировок.
Для финальной проверки истечения срока **только тестовые** LockedUntil
сдвигаются в прошлое: ждать пять минут не нужно. Настройка приложения остаётся
5 попыток / 300 секунд. Это не замер T-29 и не ускорение эскалации.

Артефакты: `artifacts/login-lockout/restart.json`, `services.log`. Контейнеры
и сеть удаляются после завершения. Рабочая база приложения не используется.

Показать код: `db/06_login_security.sql` (FOR UPDATE и часы БД),
`backend/app/routers/auth.py` (commit до HTTP-ошибки),
`backend/tests/test_login_lockout.py` (рестарт, параллельные запросы, права).

## Обновление существующей базы

Для действующего локального Compose с владельцем `medbase`:

```bash
docker compose stop backend
docker compose exec -T db psql -U medbase -d hospital_ward -v ON_ERROR_STOP=1 \
  -f /db/migrations/20261118_persistent_login_lockout.sql
docker compose up -d --build --wait backend
```

Миграция добавочная и повторяемая: пациенты, оповещения и уже накопленные
блокировки сохраняются. `db/setup.sql` пересоздаёт схему и предназначен для
чистой установки, а не обновления рабочей базы. Перед обновлением нужна копия
данных по процессу команды. Старый backend после миграции запускать нельзя:
доступ к прежнему verifier намеренно отозван.

## Ограничения

Это защита MVP внутреннего отделения. Нужны отдельные меры против массового
создания неизвестных бейджей и намеренной блокировки чужих аккаунтов, HTTPS,
секреты развёртывания и резервный этап CSRF. Администратор БД доверенный и
может менять состояние. Между репликами backend должны совпадать параметры
порога и времени блокировки.

Код подготовлен с помощью AI-ассистента; результаты проверок указываются
после фактического запуска, а SQL-часть требует ревью владельца области.

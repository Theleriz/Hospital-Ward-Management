## Демонстрация, 3–5 минут

1. Открыть `docs/sequence-diagrams.md`: вызов → опрос поста → эскалация и
   повторная эскалация; затем UC-8 с отдельной ролью старшей медсестры.
2. Показать решение 10 в `docs/decisions.md`: секунда опроса сама по себе
   не доказывает две секунды доставки, нужно измерение всего пути.
3. Открыть `docs/testing/alert-timing-report.md`: 12 показов, максимум
   1,326 с на объединённой версии; эскалации 30,013–31,034 с. Показать
   `scripts/timing/measure.py`: отправка через UI, `perf_counter`, видимость
   карточки и две проверки диапазонов времени в журнале.
4. Запустить `bash scripts/check-login-lockout.sh`. Показать пять 401, затем
   429 с верным PIN, настоящий рестарт и тот же 429. Другой бейдж входит.
5. Открыть `db/06_login_security.sql`: INSERT при отсутствии записи,
   SELECT FOR UPDATE, clock_timestamp и обновление состояния. Затем
   `backend/app/routers/auth.py`: транзакция заканчивается до HTTP-ошибки.
6. Показать `docs/testing/login-lockout-report.md`: 256 backend-тестов,
   из них 33 новых в T-48; SQL-проверки и сохранение данных при миграции.

Полный браузерный прогон запускается командой:

```bash
bash scripts/check-alert-timing.sh
```

Сборка в первый раз загружает зависимости, сами замеры занимают около четырёх
минут. На короткой защите можно показать сохранённый отчёт и объяснить метод.
